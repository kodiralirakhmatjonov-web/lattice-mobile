# Обновление цен Booking / Expedia — 9 сентября 2026

## Установка с iPhone

1. Загрузите `iumrah-business-hotel-pricing-20260909.zip` в корень текущего репозитория iumrah Business, ветка main.
2. Дождитесь завершения существующего Actions → Apply iumrah Business ZIP update. Архив автоматически распакуется и удалится; обновлённые файлы появятся отдельным коммитом.
3. Запустите Actions → Deploy iumrah Hotels Cloud → Run workflow. Это обязательно: изменение только приложения не обновляет сервер и расписание. Существующий workflow установит зависимость Cloudflare Puppeteer, применит миграцию 0033 и развернёт Worker с браузерным binding BROWSER и nodejs_compat. Новые секреты код не требует. Доступность и лимиты Browser Run зависят от аккаунта Cloudflare.
4. После успешного развёртывания сервера запустите существующую сборку TestFlight для обновления обработчика кнопки в приложении.
5. В новой версии откройте отель и нажмите «Обновить из источника». Успешный результат показывает подтверждённую цену, даже если сумма не изменилась. Ошибка источника не должна показываться как успешное обновление.

Не удаляйте базу, отели или фотографии. Архив не содержит GitHub workflows и не пытается изменить защищённые пути автоматической распаковки.

## Что обнаружено

- Импортер метаданных/фотографий работает через WKWebView. Серверное обновление цены использовало отдельный обычный fetch: выполнение JavaScript отсутствовало.
- Binding BROWSER уже присутствовал в конфигурации, но сервер цен его не использовал; отсутствовала библиотека браузерного управления.
- Booking дополнял отсутствующие даты, но не заменял прошедшие; Expedia открывал исходную ссылку без нормализации дат.
- У Share-ссылок параметры могут исчезнуть после перенаправления на страницу отеля.
- Cron выбирал только отели с существующей записью hotel_price_sources. Новый опубликованный отель без этой записи мог не получить ни одного фонового обновления.
- Кнопка Booking сначала использовала отдельный скрытый браузер iPhone, а затем другой серверный путь; этот код не мог обеспечить фоновую работу при закрытом приложении.
- Источники цен в предоставленной базе/коде — Booking и Expedia. Google используется для карт; Google Hotels/Google Travel как источник цены в этом обновлении не добавлен.

## Архитектура обновления

`Кнопка / cron → D1 lease отеля → закреплённый источник → ссылка конкретного отеля → контекст проживания → HTTP → при отсутствии цены Browser Run → проверка отеля/дат/валюты → hotel_price_cache`

Новый модуль `Backend/HotelsWorker/src/hotel-price-source.js` отделён от импорта отеля и фотографий. Он не ищет отель по названию и не переключает поставщика. Если импортер сохранил canonical_url для исходной Share-ссылки, используется именно эта связанная страница. Исходный source_url не перезаписывается.

- Цена — справочная стоимость номера на двоих, а не гарантированный тариф бронирования для любой даты поездки. Валидные будущие даты исходной ссылки сохраняются. Отсутствующие, некорректные или прошедшие даты заменяются на завтра/послезавтра (UTC), один номер, двое взрослых, без детей. Проверенные даты сохраняются с ценой в D1.
- Подтверждённая цена действует 48 часов. Cron проверяет очередь каждые 15 минут, до 12 отелей за проход. При небольшой очереди обновление начинается в ближайший проход после истечения 48 часов; при большой очереди возможна дополнительная задержка.
- Кнопка всегда обращается к источнику без ожидания TTL и без ожидания шестичасового retry. HTTP и браузерное кэширование отключены для запросов цены.
- Если этот отель уже обновляется, параллельный запрос получает понятное сообщение; второй сетевой запрос не запускается.
- При ошибке сохраняется последняя принятая цена, ошибка и следующая попытка через 6 часов. Старая цена не получает новый fetched_at как будто источник подтвердил её.
- Фоновая проверка обновляет цену источника, сохраняя ручную надбавленную/исправленную цену активной. Успешное явное нажатие кнопки возвращает отель к цене источника. Ручное изменение, сохранённое во время сетевой проверки, защищено от удаления.
- SAR → USD делится на 3.75, AED → USD на 3.6725; валюта и исходная сумма сохраняются. Неизвестные валюты не угадываются.
- Сумма за проживание делится на число ночей один раз. Добавлен разбор цены в таблице доступности Booking; исправлена возможность захватить соседнюю цену при разборе HTML-элемента.
- Резкое изменение относительно принятой цены (менее 65% или более 175%) требует второй близкой проверки (расхождение не более 8%). До подтверждения прежняя цена сохраняется. В приложении можно сразу повторить обновление.
- Новая D1-таблица hotel_price_refresh_leases защищает от одновременных запросов в разных экземплярах Worker. Истёкшая блокировка может быть занята повторно.

## Что проверено

83 автоматические проверки прошли на Node 24.19.0, включая существующие тесты репозитория и новые сценарии:

- фактическое исполнение функций Worker и их SQL на локальной SQLite;
- запись цены/валюты/дат и TTL ровно 48 часов;
- ручной запрос при свежем кэше и при отложенном retry;
- очередь cron: новые, свежие, просроченные и ошибочные записи;
- ручная цена, сбой источника, параллельное обновление и изменение цены во время запроса;
- повторная проверка резкого изменения;
- миграция и восстановление отсутствующих источников;
- перенаправление Share, устаревшие даты, HTTP/браузерный путь;
- отказ при другом отеле, постороннем домене, отсутствии даты или защитной странице;
- конвертация SAR и разбор отдельных HTML-элементов.

Проверен синтаксис изменённых JS-файлов. Импортеры в `Sources/Hotels/`, модель отеля и фотографии побайтово сохранены относительно переданного ZIP. Структура патча проверена на совместимость с текущим apply-zip.yml.

## Границы проверки — важно перед использованием

Прямой запрос 9 сентября к https://www.booking.com/Share-kDKgaGY вернул HTTP 200, но внутри была страница JavaScript/AWS WAF (3859 символов, awsWafCookieDomainList), без canonical URL, дат и цены. Это ответ защиты, а не страница отеля. Актуальную цену по этой ссылке подтвердить не удалось.

Browser Run выполняет JavaScript и ожидает загрузки страницы, но не обходит CAPTCHA и не гарантирует доступ, если Booking/Expedia блокирует облачный браузер. Такой результат сохраняется как ошибка, а не выдуманная цена. Для гарантированной доступности при постоянных блокировках нужен разрешённый поставщиком API/договорный канал тарифов; его нельзя получить одним изменением парсера.

Облачная сессия вашего Cloudflare, рабочая D1 и журнал cron здесь недоступны. Браузерные ветки тестировались с подставленными ответами, не с живым аккаунтом Browser Run. Сборка Wrangler и Xcode/TestFlight локально не выполнена: зависимость Puppeteer недоступна в локальном offline-кэше, macOS/Xcode отсутствует. Следовательно, ZIP — проверенное на локальных сценариях обновление кода, а не доказательство успешного получения живого тарифа в production. После шагов установки нужна одна реальная проверка Booking и одна Expedia.
