# iumrah Business — постоянная публичная ссылка для чтения опубликованных рейсов

## Что исправлено

- Новый стабильный read-only URL: `https://iumrah.app/flights-feed/<stable-id>`.
  Он определяется владельцем списка рейсов и не меняется при повторном подключении
  ChatGPT, повторной синхронизации, обновлении приложения или переустановке.
- `GET /flights-feed/<stable-id>` отдаёт HTML c читаемым `<pre>` и полным JSON
  (flights, comparison_key, prices, flight_count, updated_at). Поддерживается
  также `GET /flights-feed/<stable-id>.json` для обычного JSON-клиента.
- Для уже выданных старых токенов работает ссылка
  `https://iumrah.app/flights-feed/<old-token>`: ответ содержит постоянную
  ссылку владельца. **Старая ссылка `/api/catalog/hotels/flight-sync/<token>`
  остаётся без изменений**, пока токен действителен.
- Повторный `POST /api/admin/hotels/operations/flight-sync/access` больше не
  вращает токен уже включённого доступа и не отзывает выданные ссылки.
- В iumrah Business при открытии раздела опубликованных рейсов новый URL
  восстанавливается через авторизованный status endpoint и сохраняется на устройстве.
- У JSON/HTML нет TTL, ограничения чтений, авторизации и кэширования; запись
  снапшота, публикация, удаление рейсов по-прежнему требуют авторизацию.
- Ручное «Отключить доступ» по-прежнему отзывает чтение — это отдельное
  явное действие пользователя.

## Порядок развёртывания

1. Поместить ZIP `iumrah-business-*.zip` в **корень** репозитория GitHub и
   дождаться workflow **Apply iumrah Business ZIP update**.
2. Запустить **Deploy iumrah Hotels Cloud** (`workflow_dispatch`) и дождаться
   успешной проверки health endpoint. Миграция D1 не требуется.
3. **Работает без нового TestFlight:** имеющийся токен из `flight-sync/<old-token>`
   можно открыть в HTML через `flights-feed/<old-token>` — на странице будет
   стабильная ссылка. Этот HTML URL нужно один раз дать инструменту мониторинга.
4. Для автоматического отображения стабильного URL в приложении собрать
   обновлённый iumrah Business/TestFlight и открыть **Авиабилеты → Опубликованные**;
   приложение само восстановит URL. При изменении опубликованного списка
   снапшот по-прежнему синхронизируется как раньше.

## Ограничения

- Серверный read-only feed — **зеркало последнего снапшота** iumrah Business,
  а не прямой SQL-запрос к каноническому списку публикаций Package Engine.
  Пока приложение не синхронизирует опубликованные рейсы, внешняя копия
  может отставать. Поле `updated_at` показывает время последней синхронизации.
- Наличие страницы в Safari/Chrome и правильный HTTP 200 не гарантируют,
  что любое внешнее приложение или crawler всегда разрешит эту страницу;
  ограничения ChatGPT/Web и сетевые проблемы находятся вне Worker.
- Исходная переданная ZIP копия репозитория была **усечена** (отсутствует
  ZIP central directory). Файлы патча проверены по восстановленным полным
  записям `Backend/HotelsWorker` и `Sources`; полный iOS build в этой среде
  не запускался.

- `node --check Backend/HotelsWorker/src/index.js`
- `cd Backend/HotelsWorker && npm run check` — тесты стабильной ссылки включены
  в проверку Worker перед деплоем.
- `node --test Backend/HotelsWorker/tests/business-flight-sync-contract.test.mjs`
- Всё семейство старых Worker tests имеет 7 **документированных исходных
  падений и до патча**, не относящихся к Flight Sync. Новые тесты проходят.
