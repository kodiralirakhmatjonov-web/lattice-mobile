iumrah Business — Hotel Operations 005

This patch upgrades the hotel pipeline from a single-card scraper to a guarded import operation.

Included:
- direct Booking / Expedia property-link import only;
- up to four links queued and extracted sequentially;
- cross-source duplicate checks before import and after identity extraction;
- expanded property extraction: rating/review count, property class, description, check-in/out,
  amenities, services, policies, fees, room types/details, nearby places and map location;
- Google Maps link from source coordinates/address when no direct map link is exposed;
- stricter room-name validation to reject FAQ / parking / breakfast / policy text;
- server-side Cloudflare Workflow image ingestion into R2, isolated per hotel/job;
- D1 import job state and in-app progress polling;
- D1 translation cache and Workers AI translation endpoint for en / ru / uz-Latn / uz-Cyrl;
- clean white SwiftUI layouts with 18pt horizontal content margins;
- local import completion notification support when iOS can observe the finished job.

Important:
True remote push notifications after the app has been terminated still require Apple Push Notifications
capability + a refreshed provisioning profile. This patch deliberately does not alter signing entitlements.

Deployment order:
1. Apply this ZIP to the repository root.
2. Run the existing "Deploy iumrah Hotels Cloud" workflow so migration 0004 and Worker bindings are live.
3. Run the existing TestFlight workflow to build the updated native app.
